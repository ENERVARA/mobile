## Google Sign-In — also DONE ✅

Real Google account sign-in/sign-up now works on Android (`login_page.dart` /
`signup_page.dart` → `authProvider.googleSignIn()` →
`lib/core/auth/google_auth_service.dart`):

1. `google_sign_in` (v7, the Credential Manager-based API) shows the native
   account picker, initialized with the project's auto-provisioned "Web
   client" OAuth ID as `serverClientId` (required for the resulting Google ID
   token to be accepted cross-platform).
2. That Google ID token is exchanged for a **Firebase** session via
   `GoogleAuthProvider.credential` + `signInWithCredential`.
3. The resulting **Firebase** ID token (not the Google one — the backend
   verifies via Firebase Admin SDK) is sent to `POST /auth/google`, exactly
   like the web app does.
4. Logging out also signs out of both Google and Firebase, so the account
   picker doesn't silently re-auth the same account next time.

Verified with a real `flutter build apk --debug` (not just analyze). iOS needs
the Xcode capability step below before it'll work there too — the URL scheme
Google Sign-In needs (`CFBundleURLTypes` with the REVERSED_CLIENT_ID) is
already added to `Info.plist`.

## What still needs a human + a Mac (iOS only)

Android push works as-is. iOS additionally needs, in Xcode
(`ios/Runner.xcworkspace`):
1. Runner target → **Signing & Capabilities** → **+ Capability** → **Push Notifications**.
2. **+ Capability** → **Background Modes** → check **Remote notifications**.
3. An **APNs Authentication Key** from your Apple Developer account, uploaded
   at Firebase Console → Project settings → **Cloud Messaging** → Apple app
   configuration.

`Info.plist` (`UIBackgroundModes`) and a starter `Runner.entitlements` are
already in place — Xcode will link or regenerate them when you add the
capabilities above.

## How it behaves

- A device registers for push the moment a user's session hydrates
  (`auth_provider.dart` → `PushNotificationService.registerToken()` →
  `POST /api/notifications/register-token`).
- Logging out unregisters that device's token first, then clears the session.
- Foreground pushes render via `flutter_local_notifications` on the
  `enervara_default` channel (customisable per-send from the admin portal —
  title/body/image/priority/accent color/Android channel/custom data).
- Background/terminated pushes are rendered by the OS directly.
- Tapping any push navigates in-app if the notification's custom data has a
  `route` key (e.g. `route` → `/reports`) — set that field when composing in
  the [admin portal](../admin-portal).
- To resend the debug SHA-1 process for a **release** keystore later, run
  `cd android && ./gradlew signingReport` against that keystore and register
  it the same way (`firebase apps:android:sha:create`).
